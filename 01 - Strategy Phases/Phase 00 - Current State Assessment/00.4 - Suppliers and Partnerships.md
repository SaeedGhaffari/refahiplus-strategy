# 0.4 — تأمین‌کنندگان و همکاری‌های تجاری

## هدف

ثبت ساختار تأمین خدمت، وابستگی‌ها، مدل همکاری و ریسک‌های زنجیره تأمین.

## ۱. وضعیت فعلی

- به‌دلیل محدودیت بودجه، مدل غالب تأمین خدمت استفاده از API واسطه‌هاست.
- در برخی دسته‌ها قرارداد مستقیم محدود نیز وجود دارد.
- تنوع APIها از دید مدیریت در سطح قابل قبول ارزیابی شده است.
- نام اتصال‌های فعلی در [[00.2 - Product and Current Capabilities]] آمده است.
- برای خدمات پرواز و هتل، همکاری با آژانس مسافرتی دارای مجوز در حال طی فرایند حقوقی است؛ آژانس مستقل می‌ماند و قرار است رفاهی‌پلاس عامل فروش باشد.

## ۲. مدل تجاری تأمین

- درآمد غالب رفاهی‌پلاس کمیسیون تراکنش است.
- نرخ کمیسیون برای هر تأمین‌کننده به‌صورت توافقی و معمولاً ثابت تعیین می‌شود.
- رفاهی‌پلاس می‌تواند قیمت فروش و تخفیف مستقل تعیین کند.
- تسویه تأمین‌کنندگان معمولاً دوره‌ای و در بازه حدود دو هفته تا ماهانه گزارش شده است؛ شرایط هر تأمین‌کننده باید جداگانه ثبت شود.
- مدل غالب API واسطه‌ای ممکن است حاشیه سود، کنترل تجربه مشتری و قدرت مذاکره را محدود کند.

## ۳. ارزیابی هر تأمین‌کننده

برای هر اتصال، پرونده‌ای با این فیلدها تکمیل شود:

| فیلد | شرح |
|---|---|
| تأمین‌کننده/واسطه | نام شخصیت حقوقی و برند |
| دسته خدمت | پرواز، هتل، تفریح و غیره |
| نوع رابطه | API واسطه، قرارداد مستقیم، عاملیت |
| وضعیت قرارداد | امضا شده/در حال مذاکره/فاقد قرارداد |
| پوشش | شهرها، کالاها، ظرفیت و محدودیت‌ها |
| کمیسیون/قیمت | نرخ و مبنای محاسبه |
| تسویه | دوره، حداقل مبلغ، مدارک |
| استرداد | مسئولیت و زمان‌بندی |
| SLA | دسترس‌پذیری، پاسخ‌گویی و جبران |
| پشتیبانی | مسیر و زمان پاسخ |
| ریسک وابستگی | امکان جایگزینی و تمرکز |
| شواهد کیفیت | خطا، قطعی، شکایت و نرخ موفقیت |

## ۴. ریسک‌ها

- وابستگی به واسطه و تغییر شرایط API.
- تفاوت وضعیت فنی اتصال با آمادگی تجاری/قراردادی.
- ابهام در مسئولیت لغو، استرداد و پشتیبانی.
- فشار بر سرمایه در گردش در صورت فاصله زمانی پرداخت سازمان و تسویه تأمین‌کننده.
- تمرکز عرضه در چند واسطه.
- احتمال تغییر قیمت یا موجودی بین نمایش و ثبت سفارش.

## ۵. اقدامات

1. تهیه فهرست کامل تأمین‌کنندگان و قراردادها.
2. جمع‌آوری نرخ کمیسیون و شرایط تسویه.
3. بررسی SLA، فرایند استرداد و مسئولیت شکایت.
4. اندازه‌گیری کیفیت فنی APIها.
5. تعیین تأمین‌کننده جایگزین برای دسته‌های حیاتی در صورت امکان.
6. تکمیل قرارداد عاملیت آژانس و بررسی حقوقی آن.

## وضعیت تسک

**وضعیت:** مدل کلی شناخته شده؛ ماتریس تأمین‌کنندگان و مستندات قراردادها ناقص است.
